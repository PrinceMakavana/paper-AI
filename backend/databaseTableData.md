# Database Table / Collection List

This project uses MongoDB with Mongoose. The tables below are written as MongoDB collections, but the same structure can be used as SQL tables if needed.

## 1. users

Stores registered application users.

| Attribute | Type | Required | Notes |
|---|---|---:|---|
| `_id` | ObjectId | Yes | MongoDB primary key |
| `name` | String | Yes | User display name |
| `email` | String | Yes | Unique, lowercase, trimmed |
| `password` | String | Yes | Hashed password, never store plain text |
| `role` | String | Yes | Enum: `user`, `admin`; default: `user` |
| `createdAt` | Date | Yes | Auto generated by Mongoose timestamps |
| `updatedAt` | Date | Yes | Auto generated by Mongoose timestamps |

Suggested indexes:

| Index | Type | Purpose |
|---|---|---|
| `email` | Unique | Fast login and duplicate email protection |

## 2. pageindex_documents

Stores uploaded document metadata. The actual document text/vector embeddings are stored outside MongoDB in PageIndex/Pinecone depending on the route used.

| Attribute | Type | Required | Notes |
|---|---|---:|---|
| `_id` | ObjectId | Yes | MongoDB primary key |
| `user_id` | ObjectId/String | Yes | Owner user id. Prefer `ObjectId` ref to `users` for production |
| `document_id` | String | Yes | External document id from PageIndex/Pinecone/RAG upload |
| `document_name` | String | Yes | Original uploaded file name |
| `summary` | String | No | AI generated document summary |
| `page_count` | Number | No | Number of PDF pages |
| `file_size` | Number | No | Uploaded file size in bytes |
| `mime_type` | String | No | Example: `application/pdf` |
| `index_status` | String | No | Enum suggestion: `queued`, `running`, `complete`, `failed`, `unknown` |
| `error_message` | String | No | Store indexing/upload failure message |
| `createdAt` | Date | Yes | Auto generated by Mongoose timestamps |
| `updatedAt` | Date | Yes | Auto generated by Mongoose timestamps |

Suggested indexes:

| Index | Type | Purpose |
|---|---|---|
| `document_id` | Unique | Quickly find a document by external id |
| `user_id` | Normal | List documents for a user |
| `user_id, createdAt` | Compound | User document history ordered by upload time |

## 3. rag_chat_messages

Stores chat history for uploaded documents. Currently the frontend stores chat history in `localStorage`; add this collection if chat history should sync across devices or users.

| Attribute | Type | Required | Notes |
|---|---|---:|---|
| `_id` | ObjectId | Yes | MongoDB primary key |
| `user_id` | ObjectId/String | Yes | User who asked/received the message |
| `document_id` | String | Yes | Links message to uploaded document |
| `role` | String | Yes | Enum: `user`, `assistant` |
| `content` | String | Yes | Question or AI answer text |
| `chat_model` | String | No | Enum: `gemini`, `ollama` |
| `sources` | Array | No | Optional retrieved chunks/pages used for answer |
| `createdAt` | Date | Yes | Auto generated by Mongoose timestamps |
| `updatedAt` | Date | Yes | Auto generated by Mongoose timestamps |

Suggested indexes:

| Index | Type | Purpose |
|---|---|---|
| `document_id, createdAt` | Compound | Load chat history in order |
| `user_id, document_id` | Compound | Fetch one user's chat for one document |

## 4. rag_document_chunks

Optional MongoDB collection if you want to store chunk metadata locally. Full embeddings should stay in Pinecone; this table can store references for debugging, audit, or source display.

| Attribute | Type | Required | Notes |
|---|---|---:|---|
| `_id` | ObjectId | Yes | MongoDB primary key |
| `document_id` | String | Yes | Links chunk to uploaded document |
| `chunk_id` | String | Yes | Local/Pinecone vector id |
| `page_number` | Number | No | PDF page number if available |
| `chunk_index` | Number | Yes | Order of chunk in document |
| `content_preview` | String | No | Short preview only, not necessarily full text |
| `metadata` | Object | No | Loader/vector metadata |
| `createdAt` | Date | Yes | Auto generated by Mongoose timestamps |
| `updatedAt` | Date | Yes | Auto generated by Mongoose timestamps |

Suggested indexes:

| Index | Type | Purpose |
|---|---|---|
| `document_id, chunk_index` | Compound | Load chunks in document order |
| `chunk_id` | Unique | Match Mongo metadata to Pinecone vector id |

## 5. external vector store: pinecone

Pinecone is not a MongoDB table, but the RAG chat flow depends on these vector metadata fields.

| Attribute | Type | Required | Notes |
|---|---|---:|---|
| `id` | String | Yes | Pinecone vector id |
| `values` | Number[] | Yes | Embedding vector generated by selected embedding model |
| `metadata.documentId` | String | Yes | Used by `/ragchat/chat` filter |
| `metadata.source` | String | No | Source file/path from PDF loader |
| `metadata.page` | Number | No | Page number if loader provides it |
| `metadata.loc` | Object | No | LangChain PDF location metadata |

Important: `metadata.documentId` must match `pageindex_documents.document_id`.

## Current Minimum Required Collections

For the current project code, these are required first:

| Collection | Needed Now | Reason |
|---|---:|---|
| `users` | Yes | Register, login, profile |
| `pageindex_documents` | Yes | Save uploaded document metadata |
| `rag_chat_messages` | Optional | Needed only if chat history moves from frontend localStorage to backend |
| `rag_document_chunks` | Optional | Useful for source tracing/debugging; Pinecone stores vectors |
